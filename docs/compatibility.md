# Compatibility evidence, not authority

Flow Conformance Lab is independent. It does not appoint official hosts, approve implementations or certify Flow Research/Jarvis compatibility.

The published checklist requires a larger protocol proof than this release implements. Therefore **every claim artifact says Compatibility Not Proven**, even when all selected tests pass. An implementation owner can describe these specific observed results and assume responsibility for a broader claim only with the necessary additional evidence.

The upstream claim layout is preserved:

```text
Implementation: <name> <version>
Protocol compatibility: Jarvis v0.1; selected subset observed, full compatibility not proven
Conformance surface: <tested subset, checklist basis and test IDs>
Verification date: <timestamp>
Verifier: self-attested
Evidence: <run-id>/manifest.json
```

Suite version, implementation commit, exact counts, selection and limitations are separate lab evidence metadata. They are not additions to the upstream claim protocol. Output is explicitly labeled **SELF-ASSERTED COMPATIBILITY CLAIM** and includes: “This artifact is evidence generated by Flow Conformance Lab. It is not an official certification.”

The lab reports observed behavior and possible causes. A successful rejection with no exposed snapshot change cannot establish absence of hidden mutation. The demo does not prove real-world adoption. The current source discrepancy around transition payloads is recorded in research.md and each run.

Future protocol or scenario changes must bump the appropriate version. Reports embed the exact definition and references; replay refuses mismatched suite/source/test versions. Install the historical release to reproduce old scenarios instead of silently upgrading their semantics.
